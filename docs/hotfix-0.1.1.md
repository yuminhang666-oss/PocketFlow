# 0.1.1：修复 Android 账本启动及覆盖更新

日期：2026-10-17。合同 v1.0.0、数据库 schema v2 保持不变。

## 故障与原因

0.1.0 在 Android 中持续显示“正在读取账本”，预算保存失败，统计无结果。已用发布的原始 APK 在 API36 模拟器真实复现，日志报 `Failed to load dynamic library at path: libdartjni.so`。

首次依赖解析发生在 Android 平台工程生成之前，随后使用 `--no-pub` 构建，漏掉 Android 原生插件图与 Java 注册。旧 APK 缺少 GeneratedPluginRegistrant、JNI 插件类及 libdartjni.so。正式数据库连接通过 path_provider_android/JNI 取得应用目录，这一步失败使整个账本无法打开；Riverpod 默认自动重试又让错误反复表现为加载状态。

此前的 Windows 数据库与 Widget 测试使用显式注入的数据库连接，不能发现 APK 中缺少原生依赖。这是构建集成和设备验收的缺口。

## 修复

- 构建时先确认 Android 工程存在，再强制按锁解析依赖并生成原生插件配置。Gradle 在缺少插件图时直接报错。
- APK 验证检查注册类、JNI 插件类，以及每个 ABI 的 Flutter、SQLite、JNI 动态库；缺少任意项不得交付。
- 账本流的持久性错误保留为明确错误状态，只有用户点击“重试”才重新读取，避免无限加载；新增回归测试。
- 版本升至0.1.1 / versionCode 2。包名仍为cn.pocketflow，继续使用0.1.0的同一测试签名；构建前要求已有签名文件，构建后核对公开证书指纹。
- 原测试私钥保留于本机独立signing目录，另保留原缓存副本；私钥不入库、不作为发布附件，缺失时禁止自动生成替代密钥。
