## 基线发布后即可并行

- A：依共享合同做主题、首页/记账/明细/设置，注入内存替身；不得等待 B 完成后才开始 UI，也不得把替身当正式数据库。
- B：实现 LedgerRepository、BackupStore、Drift、纯预算算法与跨日刷新应用状态。
- C：使用合同夹具完成 MonthlyReportService、MarkdownExporter、BackupCodec 及图表组件；C 不自行设计交易结构。
- D：合同/预算/数据库/导出测试设计，CI流程与Android构建方案；已有授权工具可直接运行，安装或全局改动须明确范围。

## 必须等待的环节

- 所有实现分支等待 M0 的真实远程基线；环境缺失不妨碍设计，但编译/设备验证等待 M1。
- A 正式保存/额度刷新等待 B 实现与主控 composition 接线。
- C 真实数据图表和导出等待 B 的月快照；JSON codec 可先做，实际恢复等待 B 的原子 BackupStore。
- D 集成与设备验收等待相关PR及接线；APK验收不能由纯SQL测试、网页原型或源码截图替代。

阶段完成必须同时提交内容与证据，不以聊天进度替代验收。详细边界案例沿用 `03-mvp-plan.md`，发生冲突以本文件、data-contracts 与 interfaces 为准。
