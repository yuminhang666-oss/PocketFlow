# 阶段任务与验收标准

## 第一阶段 · 本次基础成果

- [x] 四个开源仓库元数据、许可证与选定源文件调查；明确从零实现。
- [x] 数据模型、整数金额、日期边界、导出/备份口径与目录设计。
- [x] 新建 Flutter 源码基础，核心算法与测试用例。
- [ ] Flutter 依赖解析、生成代码与静态检查（缺少工具链）。
- [ ] Android 平台工程（需 Flutter 生成，尚未手工伪造）。

## 第二阶段 · 能长期记账的 MVP

| 顺序 | 具体任务 | 必须通过的验收 |
| --- | --- | --- |
| 1 | 准备 Flutter/Dart、JDK、Android SDK；生成 Android 工程并解析依赖 | flutter doctor 可识别 Android 工具链；应用在模拟器或手机启动；记录版本 |
| 2 | Drift 初始化、8 类种子数据、月预算读写 | 首启无伪造消费；同一月份只一条预算；重启预算仍在 |
| 3 | 新增账单、金额键盘、日期/分类/备注 | 默认今天、默认餐饮；正常记账 ≤3 次主要操作（金额输入不计）；空金额/0/负数/三位小数/未来日期不能保存；保存失败保留输入 |
| 4 | 首页实时额度与最近账单、账单列表 | 1500−600=900，10/17 显示15天、60元/天；新增18元后显示58.80元/天；仅保存成功后关闭输入页 |
| 5 | 编辑、删除确认、历史月浏览 | 修改600→610后余额890；删除还原；移至9月后两月都刷新；取消删除不改变数据 |
| 6 | 午夜、月末、闰年、无预算、超支、错误空态 | 10/31分母1；2028/2/28分母2；2027/2/28分母1；超支保留负余额但建议额度0；历史月无当前每日额度 |
| 7 | 持久化与适配 | 强制停止/重启账单不丢；360/390/412宽度和大字体可操作，无底部遮挡；保存中禁止重复提交 |

所有验收均需可运行证据；纯设计稿、源码文件存在或工具调用成功不等于 MVP 完成。数据库与额度测试、设备类型、构建日志和 APK 路径记录至验证文档。

## 第三阶段 · 统计

分类环图、逐日柱图、余额对比线；共用整数分聚合；历史月份切换。验收：逐日/分类/逐笔金额都等于月总额；无数据没有误导性扇区；当前月未来实际值为空；点击图表可读日期/金额，颜色之外还提供图例/数字。

## 第四阶段 · Markdown + JSON

Markdown 月报与系统分享；JSON 全量备份、预检和事务恢复。验收：导出截止日期与月份正确，中文及特殊备注不破表；分享取消不丢数据；备份→干净库恢复后预算/分类/账单字段一致；破损文件/更高版本/孤立分类/重复 ID 不改变原库；零账单仍导出规范文件。

## 第五阶段 · 设备与安装包

执行核心预算单测、Drift CRUD/迁移测试、导出/恢复测试和 Android 实际适配测试；断网正常记账；无需账号与网络权限。先构建并安装本地 debug APK 验证闭环；长期使用的 release APK 需固定本地签名密钥并安全备份。发布到公共平台、建立远程仓库或上传私有资料须独立授权。

## GitHub 管理

当前目录是新项目，未创建远程仓库。基础验证通过后可按“领域与表结构 / 预算与记账 MVP / 统计 / 导出备份”分阶段提交。用户指定仓库或授权创建私有仓库后再设置 remote 与推送；个人账单和备份不进入源码仓库。
