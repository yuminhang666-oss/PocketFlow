# 0.3.3 紧急布局更新

2026-10-21。用户在 0.3.2 发布后报告账单的“收支差额”和统计的“本月净收支”金额拆行，要求 0.3.3 紧急更新并允许相关小优化。沿用本会话的 GitHub 提交/推送、PR 主控集成及应用内更新发布授权。

独立分支 `integration/v033-amount-layout`，实际远程 main / v0.3.2 基线 `de37dc008091fad265fb3f525923a0037b092eb7`，旧包 0.3.2+8，新包 0.3.3+9。原工作目录与旧交付保留。

## 原因与修复

| Before | After | Why |
| --- | --- | --- |
| MetricGrid 按原始小数字符数和固定宽度选择列数 | 测量 AmountText 实际显示的完整字符串、系统字体/字号缩放、货币符号与分组逗号 | 原来三列内负号额外占宽，softWrap 将最后一位移到第二行；卡片等高不等于金额同一行 |
| 各金额自然换行，缺乏同组排版约束 | 同组共享 16–19sp 的基础字号，保留系统缩放；仍放不下时减少列数 | 正常小额尽量维持三卡并列，大字体和长金额优先获得空间，不省略金额、不用 FittedBox 压扁用户字号 |
| 末行补空格，英文长短标题使不同行卡高变化 | 末行占满可用行宽，并按测量结果共享标题最小高度 | 保持同排金额基线、各卡片高度和相邻区域边缘稳定 |

首个显示回归在未修复代码上实际失败（文字行框不是单行）；Android16 / API36 模拟器正式 0.3.2 在 360dp、font_scale=1.15 下实际复现了负金额末位拆行。font_scale=1.0 的同设备没有复现，分别保留截图，不能混作相同环境前后对比。用户提供的真实账单截图不上传；验收使用独立虚构夹具。

## 范围

仅改公共 `metric_grid.dart`、`amount_text.dart` 的显示字符串复用、版本、离线更新记录与三语言、相关测试与交接。账单、统计、首页和预算趋势复用同一组件。没有新增依赖、业务页面或动画，输入与 Android 返回/权限行为不改。

合同 v3.1.0、金额整数分、预算/统计计算、schema4、数据库路径、JSON3/recovery3、包名、原签名及 3 秒撤销规则不变。极端聚合金额在单列仍超出时沿用完整文字换行，不作省略或隐藏精度。

## 验证与发布

新增 14 项回归覆盖金额拆行/基线、逗号宽度、末行占宽、合法金额上限与字号、空/未设值，以及两页三主题×三语言在 320dp/2倍字体下的显示。既有英文卡片等高测试保留，没有删除或放宽旧回归。

完整生成、静态检查、全量测试、Release/签名与实际覆盖结果以本轮 `docs/qa-v0.3.3.md` 和交付报告为准；不引用旧测试数量冒充本轮通过。发布继续使用 v1/v2 清单与同字节旧文件名兼容资产，完整草稿验完再设 latest。物理手机/OEM 网络仍需另验，不把模拟器或截图等同真机。
