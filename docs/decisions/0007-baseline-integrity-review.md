# ADR 0007：0.3 前置基线与恢复完整性收口

日期：2026-10-19。状态：本地主控候选，未提交/推送/合并；不是 main 已发布决策。

## 触发问题

main 仍为 0.1.1 的 8b224de，0.2/0.2.1 分别位于 PR #6/#7。#7 head f384ecf 完整包含 #6 head 081d6b4，原始提交链可以通过一个新的 main 集成 PR 保留。旧发布 tag mvp-v0.2.1-debug 指向 f384ecf，禁止改绑或覆盖资产。

S0 回归测试在原始候选上复现：公共 JSON、typed restore、私有恢复编码接受不相容的显式分类类型；模板预检同样缺失；空白分类名称可以通过。把这些问题带入新的公共基线会保留可确认的数据完整性缺口，因此在 S0 先做最小安全修复。

## 决定与边界

共享领域增加分类引用的类型校验，公共 JSON、私有恢复、数据库替换和读取共用；允许历史归档引用与旧 kind=null，不重写账目的类型、金额、日期或审计字段。名称 trim 后为空即拒绝，不默默重命名。typed restore 在创建恢复点及任何删除前完成预检。此变更收紧无效输入，不改变字段、schema 3、JSON 2 或恢复编码 2。

修正文档版本描述与 CI 的 PR 目标分支过滤。主控 codex/v030-s0-* 前缀按 ownership 明确开放；未知分支和 A–D 既有路径边界继续拒绝。

本候选不包含周期规则、分类预算、提醒、周报、分类目录迁移或反馈服务。上述范围全部保留在 0.3.0，等待 S0 经精确授权进入 main，再从实际新 main SHA 建 S1。不能因本阶段通过而称 0.3.0 完成。

## 验证与后续

干净 clone 的锁定离线解析、Drift/JIT 生成已实跑成功，未复制发布生成代码。完整结果及局限见 deliverables/v0.3.0/qa-report.md。

候选本地版本仍为 0.2.1+4，用于基线收口，不据此重新发布同名旧版本。Git 提交/推送、创建 PR、合入 main 分别等待用户对可审阅候选的授权。旧 Release、真实账本、签名和其他工作树保持不变。0.3 Release 构建和真实设备升级仍需后续执行。
