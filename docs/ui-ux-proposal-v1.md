# PocketFlow UI/UX 方案 v1

2026-10-17 · A 模块 · 合同 v1.0.0
实现基线：`26d8e4b47eef5d17fe2ca8385da3ddb58adce95e`；分支：`feat/a-ui-mvp`。
本方案基于远程 AGENTS、architecture、data-contracts、interfaces、ownership、milestones、status 与 A-ui 交接文件。

## 设计方向

面向中国大学生的安静、清晰的生活费工具。首先回答“从今天到月底，每天还能花多少”，其次解释预算与已支出。沿用现有森林绿，不用渐变、消费排名或装饰性评分。

深森林绿的每日额度区域是唯一强视觉重点；其余信息用留白、细分隔线和列表组织。主导航只有首页、统计、设置；快速记账是独立页面，移除底部导航以减少误操作。统计图表由 C 提供插槽，不重复实现计算或图表。

## 首页

```text
PocketFlow                        2026年10月 ▾
┌───────────────────────────────────────────┐
│ 从今天起 · 每日可支配                     │
│ ¥60.00 / 天                              │
│ 包含今天，距离月底还有 15 天              │
│                                           │
│ 本月预算      本月已支出      剩余预算    │
│ ¥1,500.00     ¥600.00         ¥900.00     │
│ ━━━━━━━━━━··············    已用 40%     │
└───────────────────────────────────────────┘
最近消费                           查看全部
餐饮  食堂午餐                     −¥18.00
      餐饮 · 2026-10-17
                              [＋ 记一笔]
首页                 统计                 设置
```

- 展示快照中的日额度、预算、支出、剩余预算及含今天的剩余天数。今天的建议额度即当前日均参考值，不另造每日硬上限或“今日剩余额度”。
- 三项指标在宽度不足或大字体时纵向排列。大字体下月份控件移至内容顶部，避免挤占 AppBar。
- 最近消费最多五笔，保持合同规定的顺序；完整列表惰性构建，详情可读取完整备注。领域模型已有消费时间，本次列表先用固定 localDate，避免时区更改后错示归属日。
- 右下“记一笔”始终位于导航和系统安全区上方；滚动内容预留底部空间。
- 无预算显示“待设置预算”，仍可记账；明确零预算显示 ¥0.00，不计算百分比；超支显示“已超支 ¥…”并保留日额度 ¥0.00；历史月改为结余/超支，未来月标为计划日均。
- 初次加载不显示假金额；读取失败有重试；刷新失败且有旧数据时保留旧内容并显著提示“当前显示上次结果”。月份不匹配时不把旧月数据作为新月额度展示。

## 快速记账

```text
‹ 返回                             记一笔
支出金额
¥ 18.00
[✓餐饮] [饮品] [购物] [交通]
[ 学习] [娱乐] [医疗] [其他]
日期                       2026-10-17 ›
备注                         添加备注 ›
       1             2             3
       4             5             6
       7             8             9
       .             0             ⌫
                  [ 保存支出 ]
```

- 默认今天、餐饮；稳定分类 ID 直接来自合同，不以中文名称作外键。归档分类不可新选；分类变化使原选项失效时要求重新选择。
- 字符串编辑金额，最多九位整数、两位小数；提交调用 Money.parse，不经过 double。禁止 0、负数与未来日期；第三位小数拒绝并说明，不四舍五入。
- 日期选择器限制至当天，提交时再次从注入的 Clock 校验日期。消费时间默认录入时的当地时分，回溯日期保留该时分；localDate 与 occurredAtUtcMs 分别构造，不用 UTC 转换改写归属日。
- 备注弹层使用系统文字键盘，返回后恢复金额键盘。500 的限制与合同 String.length 一致；拒绝整个超限编辑，避免截断 emoji。备注控制器由弹层生命周期管理。
- 常规竖屏键盘和保存按钮位于底部安全区；小高度、横屏或大字体改为整页滚动，允许所有字段和按钮访问。
- 保存中锁定表单、禁用重复提交及返回。Future 成功后带 LedgerEntry 返回，由调用方显示成功提示；失败留在原页，保留全部输入，不默认重试。
- 实际草稿与初始状态不同才确认放弃。正常路径为进入、可选分类、保存，金额按键不计，最多三次主要操作。

## 统计与设置

统计页保留 C 模块插槽。后续布局按分类环图、逐日柱图、余额折线图纵向安排，统一月份筛选；每区同时提供数字明细。零支出无伪造扇区；实际余额实线、均匀消费参考虚线，截止日后实际值留空。

设置按生活费管理、显示、数据管理、关于分组。提供预算编辑、历史账单、主题、月报导出、备份、恢复、关于的回调入口；未接入的动作禁用并显示“尚未开放”，不能模拟导出成功。预算弹层允许显式 0，保存失败保留输入，保存时禁止关闭。主题由 App 注入，持久化由主控接线。

## 数据与文件边界

HomePage 接收 `AsyncValue<(LedgerMonthData, BudgetSnapshot)>`：这是 UI 层组合输入，两个值须由主控从同一月快照派生；不是新增共享模型或新 Repository 合同。UI 只格式化金额与绘制进度，不复制预算算法。

QuickEntryPage 接收可用分类、Clock 和 `Future<LedgerEntry> Function(EntryDraft)`。主控绑定 `LedgerRepository.createExpense`；B 分配 ID 和审计时间，A 不写数据库。BudgetEditor 绑定 `saveBudget`。错误映射到中文，不显示 SQL、路径或原始异常。

## 预览、验证与未完成项

`design/ui-ux/preview.dart` 是明确标记“演示环境 · 示例数据不保存”的独立开发入口，复用本项目 Widget 与 B 已有算法；不由正式 main 导入、不创建第二个 APP 工程、不读写用户数据库。支持正常、空账单、未设置预算、零预算、超支、历史/未来月、加载、读取失败与保存失败。

`design-board.html` 是静态视觉样稿，使用示例金额；浏览器渲染与 Flutter 运行截图分开记录。不能用浏览器样稿替代 Android 适配验收。

本轮实现源码和交接，实际检查见 A 模块说明。Flutter 工具链缺失时不宣称 analyze、Widget 测试或真机通过。D 维护 test/，A 仅提供测试场景。正式入口接线、跨午夜状态更新、主题持久化等待主控/B；图表与文件动作等待 C。只经 PR 审查，不合并 main。
