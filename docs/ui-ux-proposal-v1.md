## 2. 设计方向

面向大学生的安静、清晰的生活费工具。首页首先回答“从今天到月底，每天还能花多少”，其次说明这个数来自哪份预算与支出。不用节省排名、消费羞辱或装饰性评分。

核心视觉是深森林绿的每日额度区域：大号数字、明确的“/ 天”、包含今天的剩余天数。只有这一块承担强视觉强调，其余信息采用留白、细分隔线和列表组织。预算使用进度仅表达事实，不把正常消费渲染为危险。

对现有设计的调整：快速记账改为独立页面，移除其底部导航；分类触控区由现有稿的 40dp 提升到至少 48dp；日期先只显示年月日，避免现有领域模型没有时间却在界面显示时分；保存前不显示自行推算的新额度。

### 字体、间距与形状

- 中文正文采用 Android 系统无衬线字体；设计稿可用 Noto Sans SC。金额采用系统数字字体及等宽数字特性；设计稿可用 Inter。首版不新增字体下载或远程字体依赖。
- 每日金额：48sp、600；页面标题：24sp、600；分区标题：18sp、600；正文：16sp；标签：14sp；辅助信息：12sp。大字体时允许换行和布局重排，不强制压缩字号。
- 间距使用 4/8/12/16/20/24/32dp。页面左右 20dp，宽度 ≥412dp 时可用 24dp；主要内容居中且最大宽度 520dp。
- 每日额度区域圆角 24dp；输入区及弹层内部容器 16dp；分类选项 12dp。普通交易列表不逐条加阴影卡片。
- 图标统一 Material Rounded，通常 24dp；所有可点击目标至少 48×48dp。主要按钮高 56dp。
- 动效只用于按压、展开和保存状态；约 150–220ms，并尊重系统减少动画设置。额度刷新不滚动跳数，不隐藏真实金额变化。

## 4. 信息架构

主导航：`首页 / 统计 / 设置`。历史账单从首页“查看全部”及设置进入。快速记账由首页“记一笔”打开；不作为第四个常驻标签。

### 首页

```text
PocketFlow                         2026年10月 ▾

┌────────────────────────────────────────────┐
│ 从今天起 · 每日可支配                      │
│ ¥ 60.00 / 天                               │
│ 包含今天，距离月底还有 15 天               │
│                                            │
│ 本月预算       本月已支出       剩余预算   │
│ ¥1,500.00      ¥600.00          ¥900.00    │
│ ━━━━━━━━━━━━━·············    已用 40%     │
└────────────────────────────────────────────┘

最近消费                            查看全部
餐饮  食堂午餐               −¥18.00
      2026年10月17日
饮品  一杯拿铁               −¥12.00
      2026年10月17日

                              [ ＋ 记一笔 ]
首页                  统计                  设置
```

- 金额示例沿用现有架构：2026-10-17，预算 1500 元，支出 600 元，余额 900 元，含今天剩余 15 天，日额度 60 元。示例明确标记 Mock，不能进入生产首启状态。
- 三项月度指标在普通字体下并排；窄屏、大字体或长金额时重排为纵向指标，保留完整金额。不能用省略号隐藏支出或超支数额。
- 每日额度区域只出现一次。“今天的建议额度”即当前日均参考值，不另造“今日剩余额度”或每日硬上限。
- 最近消费展示最多 5 笔并提供完整列表入口；使用传入的已排序记录，不在展示 Widget 中重建统计口径。
- “记一笔”使用右下方扩展按钮，始终位于底部导航和系统安全区上方；列表预留按钮高度及间距，确保最后一条不被遮挡。
- 月份选择使用底部月份面板。历史月顶部主信息改为“本月结余/已超支”；未来月标为“计划日均”。不把历史余额显示成今天可花的钱。
- 预算尚未设置仍可记账。首页提供“设置本月预算”按钮；预算表单调用现有保存接口，不自建预算计算实现。

### 快速记账

```text
‹ 返回                                 记一笔

支出金额
¥ 18.00

[✓餐饮] [饮品] [购物] [交通]
[ 学习] [娱乐] [医疗] [其他]

日期                  今天 · 2026年10月17日 ›
备注                              添加备注 ›
                         （错误显示在相关字段旁）

       1              2              3
       4              5              6
       7              8              9
       .              0              ⌫

                 [ 保存支出 ]
```

- 标准竖屏默认展示自定义数字键盘；内容区可滚动，键盘与保存按钮放在底部安全区内。横屏或可用高度不足时，整体允许滚动，不使用固定页面高度。
- 默认当天、首个有效餐饮分类；分类使用仓库稳定 ID，不能用中文名称作为 ID。八分类来自现有设计，正式名称与 ID 由主控/数据模块提供映射。
- 若分类尚未加载，显示分类区加载态并禁止保存；失败可重试，金额与备注保留。默认分类被归档时选择首个有效分类并明确显示选中项，不静默提交归档分类。
- 数字输入先保留字符串。`.` 从空值输入时显示 `0.`；单独的尾随小数点只在提交前规范为两位金额。限制两位小数、最多九位整数；第三位小数或超限输入给予字段说明，不四舍五入。
- 提交前调用 `Money.parse` 校验并要求金额大于零；禁止负数和未来日期。日期按本地日历日提交，不能因 `toUtc()` 改变所属日期。
- 点日期打开 Material 日期选择器，最大值为提交时设备当天；再次保存时重新验证当天，避免页面跨日后依赖旧值。
- 点备注打开可编辑面板和系统文字键盘；暂停显示数字键盘，完成后回到金额键盘。最多 500 个字符，计数与当前领域模型的 `String.length` 约束一致，不静默截断。
- 保存中显示“保存中…”并禁止重复提交；金额、分类、日期和备注锁定。阻止返回关闭正在保存的页面，避免保存成功后用户误认为取消并再次记账。
- 保存成功后关闭页面并提示“已保存支出”；首页等待状态流更新，不提前加账或自行算新额度。失败原地保留输入，提示“保存失败，请重试”。
- 返回时草稿有实际输入或修改才询问“放弃这笔记录？继续编辑 / 放弃”；未改动的初始空稿直接返回。
- 正常路径：进入记账、确认分类（默认餐饮可省略）、保存；金额按键不计，最多 3 次主要操作。

### 统计与设置：本轮只确定布局

统计页沿用月份筛选，包含分类环图、逐日柱状图和余额变化折线图。每区提供标题、可访问的金额明细和空态；图表点击/焦点读出日期、分类与金额。余额实际线与均匀消费参考线用实线/虚线区分；未来实际值留空。计算与数据转换由统计模块提供，本 UI 分支不引入图表依赖或聚合算法。

设置采用分组列表：生活费管理（预算、历史账单）、显示（跟随系统/浅色/深色）、数据管理（导出月报、备份、恢复）、关于。导出与恢复只调用其他模块入口；入口尚未可用时显示“尚未开放”，不能用成功提示模拟完成。主题选择立即生效；持久化方式沿用主控最终接口。

## 5. 状态与异常矩阵

| 状态 | 首页表现 | 可操作性 |
| --- | --- | --- |
| 首次加载 | 按实际布局显示静态占位，不显示假金额 | 已有有效分类时可记账 |
| 有预算、无账单 | 真实预算与日额度；“还没有消费记录” | “记第一笔” |
| 无预算、有账单 | 日额度“待设置”；支出照常显示；进度不显示 | 设置预算或继续记账 |
| 明确零预算 | ¥0.00/天；“本月预算为零”；不除以零显示百分比 | 仍可记账和调整预算 |
| 超支 | 日额度 ¥0.00；余额区改为“已超支 ¥…”，带提示图标 | 不禁止正常记账 |
| 加载失败、无旧数据 | 相关区域“暂时无法读取，请重试”，不显示 0 伪装成功 | 区域重试；入口按数据可用性启用 |
| 刷新失败、有旧数据 | 旧内容保留并标注“更新失败，当前显示上次结果” | 重试；不把旧额度表述为最新 |
| 分类不存在或归档 | 历史列表显示可获得的旧名称，否则“未识别分类” | 新账单只选择有效分类 |
| 超长备注、很多记录 | 列表备注最多两行；完整内容进入明细；长列表惰性构建 | 金额完整显示，备注可完整读取 |
| 模型解析异常 | 显示数据读取错误，不跳过异常记录伪造总额 | 重试或引导至数据维护入口 |

## 6. 已确认的数据接口与缺口

| 现有接口/字段 | UI 使用方式 | 边界 |
| --- | --- | --- |
| `LedgerRepository.watchMonth(CalendarMonth)` | 读取所选月账单状态 | 当前仅接口；返回值未承诺排序或分页 |
| `LedgerRepository.watchBudget(CalendarMonth)` | 区分未设置的 null 与显式零预算 | UI 不以零替代 null |
| `LedgerRepository.saveEntry(LedgerEntry)` | 保存入口等待 Future 完成 | 失败保留草稿；ID 及保存协调由应用层提供 |
| `LedgerRepository.saveBudget(CalendarMonth, Money)` | 预算表单保存 | 不复制预算算法 |
| `BudgetSnapshot` | 展示 month、period、budget、spent、remaining、remainingDays、dailyAllowance、isOverspent | 数值由预算模块/Provider 提供；UI 只格式化 |
| `Money.decimal / yuan / maxInputFen` | 金额显示与输入校验 | 原始金额保持整数分，不经过 double 运算 |
| `LedgerEntry.date / localDate / categoryId / note` | 列表与记账草稿映射 | 领域实体无消费时分、无分类名称；不能编造 |

尚需主控确定/提供：分类只读模型与稳定 ID、Repository 实例 Provider、预算快照 Provider、保存协调入口（含 ID 创建）、列表排序契约、刷新错误与旧数据状态、主题持久化接口、历史账单及预算设置路由。现有 main 已有 ProviderScope，但这些 Provider 尚未定义。

建议页面从 Riverpod 读取异步状态，纯组件只接收数据与回调；记账页本地草稿使用页面级状态，不把未保存输入写入仓库。接口未就绪时，Preview 可以传入明确标记的 Mock 快照与回调，不能把 Mock 数据作为生产 Provider 的回退值。
